This document describes the relational Star Schema data model designed for Power BI Desktop integration in the **E-Commerce Sales Intelligence & Demand Forecasting Platform**.

## 2. Table Specifications & Relationships

### `fact_sales` (Fact Table)
- **Granularity**: One record per order item line in a transaction.
- **Relationships**:
  - `fact_sales[date_key]` → `dim_date[date_key]` (Many-to-One, Single Filter Direction)
  - `fact_sales[customer_key]` → `dim_customer[customer_key]` (Many-to-One, Single Filter Direction)
  - `fact_sales[product_key]` → `dim_product[product_key]` (Many-to-One, Single Filter Direction)
  - `fact_sales[region_key]` → `dim_region[region_key]` (Many-to-One, Single Filter Direction)

### Dimension Tables
1. **`dim_date`**: Contains complete daily calendar dates, year, quarter, month number/name, week of year, and day name.
2. **`dim_product`**: Contains product SKU IDs, names, product categories, and baseline cost prices.
3. **`dim_customer`**: Contains unique customer identifier keys.
4. **`dim_region`**: Contains geographic sales regions (North, South, East, West, Central).

### Standalone / Analytical Tables
1. **`forecast_results`**: Contains historical demand and future predicted demand generated by Python ML champion models. Connected via `order_date` relationship to `dim_date[full_date]`.
2. **`inventory_recommendations`**: Output table from the Python recommendation engine. Connected via `product_id` relationship to `dim_product[product_id]`.
